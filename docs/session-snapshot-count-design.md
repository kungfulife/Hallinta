# Session Snapshot Count Design

## Goal

Make Manage Sessions distinguish retained snapshot files from the historical number of snapshots generated by a session.

## Data model

- Keep `SessionInfo::snapshot_count` as the persisted lifetime-generated count for compatibility with existing session metadata.
- Add a runtime-only retained snapshot count to `SessionInfo`. It is omitted from `session.json` and populated when sessions are listed by counting files accepted by the existing monitor-snapshot filename filter.
- Avoid file-system access in the UI renderer.

## Interface

Each session row shows:

1. `Snapshots: <retained files> / <configured maximum>` as the normal primary count.
2. `Generated total: <lifetime count>` directly below it in smaller, muted text.

The retained count refreshes after snapshot retention cleanup, so a live session settles on the exact files present on disk.

## Compatibility and errors

- Existing `session.json` files remain unchanged and require no migration.
- Unreadable or vanished directory entries are not counted; existing session-list behavior continues to skip invalid session metadata.
- Version remains 0.8.7.

## Verification

- Add regression coverage proving a lifetime total above the limit can coexist with a retained count at or below the limit.
- Test the two label formats, including the smaller secondary presentation through the renderer where practical.
- Run formatting, unit tests, Clippy with warnings denied, a release build, and a read-only Grok review before the test handoff.

## Release boundary

Commit and build locally for operator testing. Do not push, move the `v0.8.7` tag, delete the existing release, or republish until the operator explicitly approves the tested build.
